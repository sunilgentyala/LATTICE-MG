LATTICE-MG

Cross-Modal, Temporal, and Agent-Delegation Defenses Against Jailbreaks in Text-to-Image and Text-to-Video Generation

Jailbreak research for generative media usually evaluates one modality, one frame, or one prompt filter at a time. That misses three real failure modes: text and an image can be safe alone but unsafe together, a video can look safe at every sampled frame yet unsafe in the transition between two benign states, and an agent can hop to a weaker provider or a broader operation than a human approved. LATTICE-MG binds cross-modal intent, temporal video risk, and agent tool-delegation into one signed policy contract instead of three disconnected classifiers.

The gap

Model names aren't security boundaries

Published evaluations often compare product names (Grok, ChatGPT, Sora, Claude Code) as if they were equivalent systems. They aren't: a native generator, a dedicated video model, and an agent that invokes external tools expose different interfaces, different policies, and different failure modes.

What a single-channel defense sees

A prompt filter sees text. An output classifier sees one image or a sparsely sampled frame. A tool allowlist sees which server was called. Each one is blind to everything outside its channel: composition across modalities, drift across turns, and the transition between two benign frames.

What LATTICE-MG binds together

One Cross-Modal Safety Contract per request, carrying the normalized intent, the cross-modal composition score, identity/consent state, and the exact authorized operation, enforced end-to-end by a Tool Authorization Manifest and a Temporal Risk Lattice, not three independent classifiers that can each be satisfied in isolation.

How it works

Contract, manifest, lattice, decision

The same normalized intent is bound to the exact provider, model, operation, assets, temporal inspection plan, consent state, and evidence record, so a downstream tool cannot silently change the operation without invalidating the contract.

1. Cross-Modal Safety Contract (CMSC)Signed, canonical record of normalized intent, risk vector, identity/consent, operation limits, and required inspection depth, HMAC-bound in this implementation.
→
2. Tool Authorization Manifest (TAM)Authorizes an exact provider/endpoint/model/account/region/action for agent-mediated generation, not merely an allowlisted server. Denies provider hops and undocumented model substitution.
3. Temporal Risk LatticeAdaptive-density windows plus transition scores between boundary states: r_video = max(max window risk, max transition risk, cumulative risk, boundary-pair risk).
→
4. Four-way decision D(R)ALLOW, CONSTRAINED ALLOW, REVIEW, or REFUSE, gated on every category risk being below threshold and the identity, tool, lineage, and inspection invariants all holding.
Formal core (Eq. 1–3), implemented and tested: the pre-generation risk score r_pre = σ(w·s + γ·Φ(G(R))) with the cross-modal composition term Φ, the ALLOW gate over per-category thresholds and gate invariants, and r_video combining window, transition, cumulative, and boundary-pair risk: see lattice_mg/risk.py and lattice_mg/temporal.py.

Limitations

  • Detection/false-positive probabilities in lattice_mg/baselines.py are illustrative defaults, not measurements from any real system; inspect and replace them before drawing platform-specific conclusions.
  • The CMSC signature uses HMAC-SHA256 for tamper-evidence in this reference implementation; production deployment would use an asymmetric signature tied to the enforcement service's key material.
  • The intent graph and temporal lattice operate on declared schema features here, not real vision/ASR/OCR models; wiring in real multimodal detectors is future work.
  • This does not replace the authorized, preregistered, multi-platform empirical evaluation the paper defines in Section VII; it is a reproducibility artifact for the architecture's design claims.
